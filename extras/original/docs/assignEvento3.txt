SYSTEM:
You are a careful clinical claims auditor.
Your job is to determine which rubric rules (if any) match a single claims event.
Be conservative and precise.

USER:
TASK
Given:
1) a list of rubric rules, and
2) one real-world claims event,

identify which rules the event truly matches.

This pass is for QUALITY CHECKING a faster model’s output.
Do NOT be lenient.
Do NOT invent matches.
It is acceptable to return zero matches.

INPUTS

RUBRIC_RULES_JSON:
{{RULES_SIMPLE_LIST_JSON}}

EVENT_JSON:
{{ONE_EVENT_JSON}}

GUIDELINES
- Evaluate ALL rules in RUBRIC_RULES_JSON.
- Match a rule only if the event clearly aligns with the rule’s meaning.
- Use domain + keywords + timing if available.
- If a rule has a time window and the event has a relative day, enforce it.
- If a rule implies a care setting (inpatient/ED) and the event contradicts it, do NOT match.
- If information is missing, you may still match but lower confidence.
- Do NOT decide patient-level YES/NO.
- Do NOT apply thresholds or exclusions beyond the single event.

OUTPUT
Return STRICT JSON ONLY.

{
  "event_id": "<copy from EVENT_JSON if present, else 'UNKNOWN'>",
  "matched_rules": [
    {
      "rule_uid": "<string>",
      "confidence": 0.0,
      "reason": "<short explanation of why this event matches the rule>"
    }
  ],
  "notes": "<optional short note if no rules matched or if data was missing>"
}

RULES
- confidence should reflect how sure you are THIS EVENT matches THIS RULE (not diagnosis probability).
- Keep the matched_rules list short (usually 0–2).
- If no rules match, return matched_rules = [].
- NEVER return null.
